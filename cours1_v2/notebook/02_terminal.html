Le terminal#

Les outils employés dans la suite du module, comme python, conda et git, s’utilisent en ligne de commande, dans un terminal. Les programmes écrits dans le module se lancent aussi de cette façon, car un programme sans fenêtre ni bouton est plus simple à écrire. Dans le TD 1b, on refait au clavier, dans Git Bash, ce que le TD 1a fait à la souris : se déplacer dans les dossiers, copier, renommer et ouvrir des fichiers.

Interface graphique et ligne de commande#

Dans une interface graphique, on choisit l’opération parmi les menus et les boutons affichés. En ligne de commande, on tape une commande, le nom de l’opération, puis ses paramètres. Il faut donc connaître ce nom, ou le chercher dans l’aide. Les sigles anglais sont GUI (graphical user interface) et CLI (command-line interface).

Dans l’explorateur, la copie demande ensuite d’ouvrir le dossier travail, puis de choisir Coller au clic droit. Dans Git Bash, on tape la ligne, puis on appuie sur Entrée. Les deux copies donnent le même fichier, travail/raven.odt.

cp abrège copy, et n’affiche rien quand la copie réussit. Ses deux paramètres sont le fichier à copier et le dossier de destination.

Intérêt de la ligne de commande#

Face à une interface graphique, la ligne de commande facilite l’automatisation des tâches, et simplifie l’écriture d’un programme. Savoir s’en servir donne aussi accès aux outils qui n’ont pas d’autre interface.

Automatisation des tâches#

Le traitement par lot applique la même opération à une série de fichiers. Il est plus courant en ligne de commande qu’en interface graphique. La commande suivante copie d’un coup les fichiers .txt du dossier depart dans le dossier travail/textes, comme au TD 1b :

cp depart/*.txt travail/textes/

Pour réduire 120 images à 640 pixels de large dans Paint, il faut ouvrir, redimensionner et enregistrer chaque image, 120 fois. En ligne de commande, une seule commande traite toutes les images :

magick mogrify -path travail -resize 640 depart/*.png

Le motif depart/*.png désigne tous les fichiers .png de depart/. Le programme magick, d’ImageMagick, sert seulement d’exemple, et le module ne l’emploie pas.

Une suite de commandes s’enregistre dans un script, et se relance avec d’autres paramètres. La page Premier programme en donne un exemple. Des logiciels à interface graphique proposent aussi un traitement par lot, limité aux opérations qu’ils prévoient. QGIS le propose par « Exécuter comme processus de lot », dans la boîte à outils de traitements.

Programmes plus simples à écrire#

Un programme en ligne de commande reçoit ses paramètres sur la ligne qui le lance. Le cours 3 construit le programme suivant, qui reçoit un nom de fichier, trace.csv, et une option, -s 2 :

python altitudes.py trace.csv -s 2

Avec une interface graphique, il faudrait aussi programmer les fenêtres, les boutons et leur comportement. Un programme en ligne de commande peut en outre être lancé par un autre programme, comme au cours 5.

Logiciels scientifiques et serveurs de calcul#

Beaucoup de logiciels scientifiques ne s’utilisent qu’en ligne de commande, comme GDAL pour les données géographiques, PDAL pour les nuages de points, ou MicMac, de l’IGN et de l’ENSG, qui se lance par la commande mm3d. La commande suivante convertit l’image carte.png en carte.tif avec gdal_translate, un programme de GDAL :

gdal_translate carte.png carte.tif

QGIS propose des fenêtres pour une partie des programmes de GDAL. Les serveurs de calcul s’utilisent à distance, sans interface graphique. On s’y connecte par ssh, présenté au cours 6.

Le terminal et l’interpréteur de commandes#

Deux programmes se partagent le travail :

  • le terminal est la fenêtre : il affiche du texte et transmet ce qu’on tape ;

  • l’interpréteur de commandes, ou shell, lit chaque ligne et lance le programme qu’elle nomme.

Quand le programme a fini, l’interpréteur réaffiche l’invite, et attend la ligne suivante. Le mot « terminal » désigne souvent les deux programmes à la fois. Le langage des commandes est celui de l’interpréteur : cmd, PowerShell ou bash. L’interpréteur Python, présenté dans la page Premier programme, lit lui aussi du texte et le fait exécuter.

Sous Windows 11, « Open Git Bash here » se trouve sous « Afficher d’autres options », dans le menu du clic droit. Git Bash s’ouvre aussi depuis le menu Démarrer.

Le module emploie Git Bash, installé avec git sur les postes. Son interpréteur, bash, n’est pas fourni avec Windows. bash est l’interpréteur de Linux et de la plupart des serveurs. Ce choix s’appuie sur les faits suivants :

  • 92 % des serveurs web sont sous Unix, dont Linux (W3Techs, septembre 2026), et les 500 ordinateurs du classement TOP500 sont sous Linux depuis novembre 2017 ;

  • bash est employé par 49 % des développeurs, contre 23 % pour PowerShell (enquête Stack Overflow 2025) ;

  • Git Bash fournit aussi ssh, employé au cours 6 ;

  • sous macOS, l’interpréteur par défaut, zsh, est très proche de bash, et les commandes du module s’y tapent à l’identique.

PowerShell n’est pas employé dans le module. Sur les postes de la salle, sans droits d’administrateur, il n’exécute pas le script d’activation de conda, et affiche activate.ps1 cannot be loaded because running scripts is disabled on this system.

Structure d’une commande#

Une commande commence par le nom du programme à lancer. Suivent des options, qui commencent par un tiret, et des arguments, souvent des noms de fichiers :

commande [options] <arguments>

Les crochets désignent ce qui est facultatif, les chevrons ce qu’on remplace.

--help

  • Une option d’une lettre prend un tiret, une option en toutes lettres en prend deux.

  • --help affiche l’aide de la plupart des commandes.

  • L’interpréteur découpe la ligne aux espaces. Le premier mot désigne le programme, et les mots suivants lui sont transmis. Un nom de fichier qui contient un espace s’écrit donc entre guillemets : cp depart/raven_une_ligne.txt "travail/le corbeau.txt".

Note

Un chemin copié depuis la barre d’adresse de l’explorateur garde ses \. Dans Git Bash, il s’écrit entre guillemets : cd "C:\Users\eleve\Desktop". Sur un clavier français, ~ se tape AltGr + 2, puis espace.

Un programme ne connaît pas à l’avance le chemin absolu du dossier d’un utilisateur, mais il peut s’appuyer sur la position relative des fichiers. Un projet qui n’emploie que des chemins relatifs se copie, se déplace et s’envoie sans modification ; un chemin absolu écrit dans le code ne vaut que sur le poste où il a été écrit. Le TD 2b fait corriger un chemin de ce genre.

Le fichier exécutable d’une commande#

Une commande lance un fichier exécutable. which affiche le chemin de ce fichier, et ce chemin peut remplacer le nom de la commande :

$ which notepad
/c/Windows/system32/notepad
$ /c/Windows/system32/notepad.exe depart/raven_une_ligne.txt

La seconde commande ouvre le poème dans le Bloc-notes, comme notepad depart/raven_une_ligne.txt. Le chemin /c/Windows/system32/notepad.exe désigne le fichier C:\Windows\System32\notepad.exe de l’explorateur.

Commande tapée

Fichier lancé

notepad fichier

le premier fichier notepad trouvé dans les dossiers du PATH, ici /c/Windows/system32/notepad

/c/Windows/system32/notepad.exe fichier

le fichier de ce chemin, sans recherche

La variable PATH contient une liste de dossiers. Pour trouver le fichier d’une commande, Git Bash parcourt ces dossiers dans l’ordre, et lance le premier fichier qui porte ce nom. echo $PATH affiche cette liste. Quand plusieurs versions d’un programme sont installées sur le poste, comme Python au TD 1c, il faut donc écrire le chemin du fichier, ou régler le PATH.

Au TD 1c, conda ajoute son dossier en tête du PATH, et python lance alors le Python d’Anaconda. La section Compilateur et interpréteur : changer de poste montre la liste des dossiers du PATH, avant et après le réglage de conda.

Note

which ls affiche /usr/bin/ls. Git Bash appelle / son dossier d’installation, C:\Program Files\Git, et ce fichier est donc C:\Program Files\Git\usr\bin\ls.exe ; cygpath -w /usr/bin/ls affiche ce chemin. Seuls les chemins qui commencent par /c/ suivent la règle de la section précédente. Dans l’invite de commandes, where notepad affiche le même fichier que which notepad, et dans PowerShell, Get-Command notepad.

Fichiers cachés et caractère générique *#

Les exemples suivants portent sur le dossier du TD 1b, tel qu’il est livré.

1b_terminal/
├── depart/
│   ├── auld_lang_syne.odt
│   ├── auld_lang_syne_une_ligne.donnees
│   ├── auld_lang_syne_une_ligne.txt
│   ├── raven.odt
│   ├── raven_une_ligne.donnees
│   └── raven_une_ligne.txt
└── travail/           vide

Un nom qui commence par un point désigne un fichier caché : ls ne l’affiche pas, ls -a l’affiche. Dans le dossier travail, encore vide :

$ ls travail
$ ls -a travail
./  ../

. et .., le dossier courant et son parent, sont les deux entrées cachées de tout dossier. Les logiciels enregistrent leurs réglages dans des fichiers cachés : le TD 1c crée .bash_profile dans le dossier personnel, et le cours 2 un dossier caché, .git.

Note

Dans l’explorateur de Windows, les fichiers cachés s’affichent par le menu Affichage, Afficher, Éléments masqués. Windows marque un fichier caché par un attribut. Git Bash suit la convention du point, celle de Linux et de macOS.

Dans un nom de fichier, le caractère générique * remplace n’importe quelle suite de caractères. Git Bash remplace le motif, par exemple *.txt, par la liste des noms qui correspondent, puis lance la commande.

Commande

Noms désignés dans depart/ du TD 1b

ls depart/*.txt

les deux fichiers .txt

ls depart/raven*

les trois fichiers de The Raven

cp depart/*.odt travail/

les deux documents LibreOffice

Note

Le caractère * s’appelle aussi joker (wildcard en anglais), et ces motifs s’appellent glob. Le cours 3 emploie ce mot avec Path.glob. Les expressions régulières, employées par grep ou le module re de Python, ont une autre syntaxe, où * répète le caractère précédent.
